# Incident Report / Post-Mortem — required sections

1. **Incident Timeline** — detection time, response time, resolution time, close time
2. **Impact Assessment** — users affected, services degraded, SLA breach (yes/no)
3. **Root Cause Analysis** — 5 Whys or Fishbone format
4. **Corrective Actions** — immediate fixes applied during the incident
5. **Preventive Actions** — changes that prevent recurrence, with owners and dates
6. **Lessons Learned** — what went well, what didn't, what to change
7. **Follow-Up Action Items** — tracked items with owners and due dates

## Quality bar

Root cause must go deep enough. "The link went down" is not a root cause —
WHY did the link go down?

Blameless: describe systems and decisions, not individuals.
